# 对抗验证 lens

对抗独立性纪律：攻击者与作者分离——新生上下文（子代理或新会话），拿得到同等证据（读同一批文件与命令输出），只读不改。同一 agent 换口气重读自己的产出是自确认（generator/evaluator 未分离）。无子代理宿主降级：新会话审查，或 review 自审清单，日志如实标注「降级自审」。

三个互补 lens，按该轮风险选一至三个：

## 红队（默认）

专找漏洞：判据歧义、证据链断点、反例场景。发现按 Critical/Important/Minor 排序，每条＝问题＋一个具体场景＋修订建议。攻击对象是该轮 Spec 与实施产物。

## 魔鬼代言人（方案级）

假设方案是错的：是否过度工程、砍掉哪层仍解决主要问题、更便宜的替代是什么、哪些修订建议其实该拒绝。总裁决：批准 / 修改后批准 / 推倒重来。

## 第三方用户视角（交付面）

扮演装完就用的第三方：在空 AGENTS.md、无脚本、无 CI 的项目里，对每条能力问「它怎么到我手上」；文档承诺与实际交付是否一致；有没有只落在作者环境、没到用户手上的断链。

## 裁决规则

- Critical 未解决＝该结论记「未被确认」，不得作为下一轮假设的前提。
- 攻击发现的错误回 `implement` 修复后复验受影响部分；修复优先于开新轮。
