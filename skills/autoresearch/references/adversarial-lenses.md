# 对抗验证 lens

对抗独立性纪律：攻击者与作者分离——新生上下文（子代理或新会话），拿得到同等证据（读同一批文件与命令输出），只读不改。同一 agent 换口气重读自己的产出是自确认（generator/evaluator 未分离）。无子代理宿主降级为自审时：仍须记录具体攻击与至少一个反例尝试，输出明确标注 self——降级标注不能替代攻击记录，self 不称独立验证。需要用户另开会话审查时，交接最小包＝原问题、获批包、证据位置、待审声明。

攻击对象：本轮**获批包、观察、结论与重开提案**。三个互补 lens，按该轮风险选一至三个：

## 红队（默认）

专找漏洞：判据歧义、证据链断点、反例场景、重开提案的排除法三问是否属实。发现按 Critical/Important/Minor 排序（阻断级沿用 review 定义：Critical 与阻断性 Important），每条＝问题＋一个具体场景＋修订建议。

## 魔鬼代言人（方案级）

假设方案是错的：是否过度工程、砍掉哪层仍解决主要问题、更便宜的替代是什么、哪些修订建议其实该拒绝。总裁决：批准 / 修改后批准 / 推倒重来。

## 第三方用户视角（交付面）

扮演装完就用的第三方：在空 AGENTS.md、无脚本、无 CI、可能缺配套 skill 的项目里，对每条能力问「它怎么到我手上」；文档承诺与实际交付是否一致。

## 裁决规则

- 阻断级发现未解决＝该结论记「未被确认」，不得作为下一轮假设的前提。
- 攻击发现的错误回 `implement` 修复后只复验受影响部分（计入预算）；修复优先于开新轮。
