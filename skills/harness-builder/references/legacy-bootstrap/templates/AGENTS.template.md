## 状态与恢复

- 再读 `progress.md` 最新记录。
- 需要设计、风险、引用或根因时读 `findings.md`。

## 通用 Harness 规则

- 先诊断 harness，再归因模型：失败时先检查任务边界、上下文、工具 / 环境、状态文件、验证反馈和生命周期。
- 仓库是真相来源：计划、进度、证据、风险和根因必须落到仓库文件；聊天记录不能作为唯一依据。
- 保持 `AGENTS.md` 薄入口：这里只放稳定规则、项目地图、验证入口和恢复指针；临时任务状态写入三文件。
- 非平凡实现前先确认项目工作面：入口、依赖、运行命令、验证命令、项目级 MCP / capability、恢复路径和能力缺口都要清楚。
- 默认 WIP=1：当前 active slice 未验证、阻塞或明确放弃前，不开启无关工作。
- 没有 fresh evidence 不声明完成：完成结论必须对应当前命令、测试、smoke / E2E 或明确的未验证限制。
- 文档随行为变化更新：修改代码、命令、配置、验证路径或用户可见行为时，同步 README / docs / 三文件。
- Git checkpoint 要干净：每个计划阶段验证成功后提交；commit 应小而原子，信息说明行为和原因；不改写历史、不清理分支、不提交无关 dirty files。
- 收尾要降低熵：清理临时文件、过期 TODO、误导性状态和重复规则；高风险删除或重构先提出方案。
