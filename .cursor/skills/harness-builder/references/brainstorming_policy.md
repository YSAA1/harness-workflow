# Brainstorming Policy

Harness Builder should not ask a fixed questionnaire. The purpose of brainstorming is to discover the missing information needed to build the right harness for this project.

Ask only questions that change the harness design. Every question must include why it matters, which harness component it affects, and what conservative default will be used if unanswered.

Before a Harness Plan is written, evidence or user answers must cover target outcome, non-goals, acceptance criteria, verification path, evidence location, and source-of-truth priority. `No user questions needed` is valid only when these are already answered by the user request, approved Spec/Plan, or repo artifacts.

End brainstorming with a Harness Hypothesis that lists known repo facts, known user facts, missing information, questions, assumptions if unanswered, and course coverage check.
