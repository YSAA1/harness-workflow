# Placement decisions
Stable project-wide contracts go in AGENTS; local contracts go in subdirectory entries; long explanations go in existing docs; task state/evidence goes in the selected recovery backend; repeated workflows may become a skill.
Verification prefers commands that already exist for the target platform; do not force scripts/agent/check.sh. For external capabilities, reuse existing tools/connectors first.
Hooks apply only to explicit, testable automation needs; sample string matching is not a permission or security boundary. Install and verify a specific hook only when the user asks.
Add a component only when it resolves a real gap at a reasonable maintenance cost.
Every harness component is a temporary hypothesis about a current model capability gap; when the failure a component guards against no longer occurs, remove or downgrade it, with removal evidenced by actual task records — nothing is kept just because "it has always been this way".
