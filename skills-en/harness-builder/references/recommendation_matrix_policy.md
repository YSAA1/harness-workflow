# Recommendation matrix
Multi-domain workbench rework can use one table: gap/evidence, minimal treatment, owner, verification. A single small fix can be a short sentence; empty categories need no placeholder rows.
Required / Recommended / Deferred / Rejected describe priority and choice; they grant no installation permission.
Check entries, recovery, verification or capabilities relevant to the current goal; do not pad one row per category for skills/hooks/MCP/subagents/plugins/CI.
Complex rows can go to the corresponding helper; a small pointer fix needs no full workflow invocation. Existing authorizations carry across helpers, avoiding repeated USER CHECKPOINTs.
When existing capabilities can solve it, add no new tool; when candidate facts need current information, check official sources.
