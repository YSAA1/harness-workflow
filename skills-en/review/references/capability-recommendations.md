# Verification capability gaps
First check whether existing commands, environments, and tools can cover the required claims. Fixing an ordinary entry point does not automatically escalate into harness-builder.
When a gap genuinely requires new capability, use capability-recommender, listing the gap, available substitutes, candidate value, installation scope, and minimal verification.
A missing tool does not mean the task failed, but when a required acceptance is missing, the verdict is unknown. Do not auto-install or lower the acceptance contract.
