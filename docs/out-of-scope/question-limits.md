# 不设提问轮数上限

**拒绝内容**：给 `brainstorm`（或其他访谈式技能）加提问次数/轮数的硬上限或可配置配额。

**理由**：拷问刻意开放——一直挖到设计树每个分支都定下来；有的方案三个问题就够，有的要五十个。固定上限要么在难题上截断有用的探索，要么在简单题上显得随意。还会混淆两种故障：方案确实欠规格导致问得多（正常工作），与问了冗余低价值问题（提示质量问题，修在技能正文，不靠计数器）。

**替代做法**：

- 用档位（低/中/高）调问题面宽度与拷问强度，档位不是轮数配额。
- 用户随时可叫停并接受当前方案，或让它收尾、总结、往下走——自然语言是预期的控制面。
