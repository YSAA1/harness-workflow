harness-builder

这是跨工作台问题的总控；交付与缺口相称的配置或建议，不把完整工作流当作所有任务前置条件。

brainstorm

构思 Spec · 30 行 · 0 个流程步

把开放需求变成可执行的设计决定。先利用用户材料、现有规格和代码回答事实问题；只问答案会改变结果的未定取舍。

5 个 reference 0 条验收项

plan

Executable Plan · 31 行 · 0 个流程步

计划说明做什么、先后关系及如何验收，复用用户请求、已批准 Spec、issue 和现有项目记录，不要求再创建一套需求材料。

0 个 reference 0 条验收项

implement

小步执行 · 35 行 · 0 个流程步

用户请求、项目规格或计划可直接提供执行范围。无需为常规修改补齐全部流程工件。

1 个 reference 0 条验收项

diagnose

失败诊断 · 30 行 · 0 个流程步

将用户描述的故障与真实环境对应，区分现象、假设、已证实原因和修复证据。不要用隐藏错误、跳过测试或扩大容错来冒充修复。

1 个 reference 0 条验收项

review

证据评审 · 40 行 · 0 个流程步

把问题发现和完成声明的证据核对放在一次评审中。审阅范围来自用户请求；WIP 可报告 findings，不必先完成实现才能审阅。

7 个 reference 0 条验收项

verify

review 兼容别名 · 13 行 · 0 个流程步

执行 ../review/SKILL.md 的相关证据核对部分；保留用户指定范围。已有适用检查不重复运行，也不强制额外对抗审查。

0 个 reference 0 条验收项

cleanup

Knowledge Cleanup · 31 行 · 0 个流程步

使本次任务的记录与实际结果一致。完成、阻塞、放弃和交接都可整理，不要求先获得 ready 才能记录未完成工作。
