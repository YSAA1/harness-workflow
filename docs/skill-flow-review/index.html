brainstorm

构思 Spec · 121 行 · 2 个流程步

- 防止模糊想法过早进入计划或实现。 - 在选择方案前先把验证策略说清楚。 - 通过独立 Spec 留下 goals、non-goals、方案取舍、成功标准和 plan handoff。

5 个 reference 3 条验收项

plan

Executable Plan · 148 行 · 5 个流程步

- 把计划从聊天迁移到仓库 artifact，让压缩或新会话后仍能恢复边界、checkbox 进度和证明方式。 - 让多 agent / 多 session 能回答"现在做到哪、下一步是什么、如何证明完成"。 - 在计划阶段暴露验证能力、fallback 和 commit gate，避免做完后才发现无法证明。

0 个 reference 7 条验收项

implement

小步执行 · 191 行 · 8 个流程步

- 当前 active slice 没拿到证据前，不开新 slice。 - 修代码就同步命令、文档或 recovery surface，否则下次会话恢复会失真。 - 验证强度按风险匹配，不机械要求覆盖率。 - 本 lane 可以跑局部检查，但不能声明 ready；ready claim 只能由 verify 证明。 - 失败了不靠猜，转 diagnose。

1 个 reference 6 条验收项

diagnose

失败诊断 · 155 行 · 8 个流程步

- 没有可复现失败，不提修复结论。 - 没有 root cause 证据，不算诊断完成。 - 不在 build/test/lint 已红的状态下推进 implementation。 - 修复必须最小、单一、可验证。 - 三轮 hypothesis 仍找不到根因，升级为 blocker。

verify

最终验证 · 231 行 · 8 个流程步

把"可以结束"转化为可追溯证据：每条成功标准都必须对应 fresh command、smoke/E2E 或明确的未验证限制。 用结构化 verification record 绑定 claim、路径、最后改动、命令、跳过项、unknown 和 ready verdict。

2 个 reference 9 条验收项

cleanup

Knowledge Cleanup · 188 行 · 7 个流程步

- 保持 AGENTS.md 是薄规则手册，不写 changelog、临时状态或会话叙事。 - 确保 README、docs、generated artifacts 和验证命令描述当前真实项目。 - 检查 recovery surface 是否漂移、膨胀或与 git diff 矛盾。 - 把未解决的 doc drift 和 residual risk 记录成明确 follow-up。
