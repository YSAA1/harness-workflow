执行流程

1

Evidence gate — Collect repo evidence before questions or installation (AGENTS.md/CLAUDE.md, README, docs, scripts, tests, CI, git, .harness/, skills dirs). Do not start by generating files. Read any supplied task/feature/bug context as harness-design evidence, not as a task to execute. Do not invent acceptance criteria; route unclear goals to brainstorm / plan. Probe cheap dynamic context (git status, diagnostics, CI if available). Optionally use scripts/scan_project.py.

2

Question gate — Ask only questions that change harness design (target outcome, non-goals, acceptance criteria, verification depth, source of truth). If none needed: No user questions needed plus evidence-backed assumptions.

3

Mode + Harness Hypothesis + recommendation contract — Pick Quick repair or Full recommendation, then state known facts, dynamic state, intent, missing info, questions, assumptions, objective, non-goals, verification path, evidence basis, selected recovery surface, source-of-truth priority, and existing components to keep/patch/archive/reject. Unknown fields → ask or route; no template filler.

4

Recommendation table — One Required / Recommended / Deferred / Rejected table. Quick repair only covers: agent entry and project map; static docs and durable rules; recovery surface; recovery policy and work index; verification entry; anti-entropy. Full recommendation adds architecture boundaries, skills, hooks, MCP, subagents, plugins, commands/CI/headless automation, external research, dynamic context, and commit protocol (default Deferred). See references/recommendation_matrix_policy.md, references/recovery_policy.md, references/source_of_truth_tiers.md, references/living_docs_discipline.md, references/architecture_enforcement_policy.md, references/anti_entropy.md, and references/automation_recommendation_guide.md.

5

Capability Recommendation pass — Run only for Full recommendation or a concrete Quick repair capability gap. Bind each candidate to one recommendation row and show enough detail to act: type, recommendation, repo signal, why, install surface, approval needed, fallback, verification probe, and priority/classification. Default 1-2 candidates per relevant category. If the user explicitly asks for setup or installation recommendations, cover MCP, skills, hooks, subagents, plugins, and commands/CI/headless automation with candidates or clear defer/reject reasons. Do not stop at installed/local skills; use references/capability_discovery_playbook.md, automation_recommendation_guide.md, the automation_* references, $find-skills / find-skills, targeted web search, or local official docs when repo evidence points to ecosystem-specific tools. In Quick repair with no capability gap, record No capability recommendation needed, No reusable skill search needed, and No web research needed with evidence-backed reasons.

6

Verification design gate — Fast check, deeper smoke/E2E/manual check, evidence location, unverified risks, and per-phase acceptance before installation.

7

User checkpoint — Only ask for approval when there is at least one concrete install, patch, archive, or config action. If there is no action to approve, say No install recommended and stop with the recommendation summary.

8

Approved install phase — Install or patch only approved project-local items; Required only unless the user approves more. Quick repair installs only the required entry/recovery/verification patches. Prefer AGENTS.md, scripts/agent/check.sh, docs, .harness/*, .agents/skills/*, and templates. Recovery backend options: none, lightweight, harness, feature-list, existing. Map runtime fields: .harness/state.md (hot index), .harness/progress.md (evidence), .harness/decisions.md (decisions); recovery_policy.md and work_index.md Required when recovery ≠ none. No root-level legacy state files.

9

Verification — After installation, run validation and phase checks, or record blockers. No fresh evidence → no ready claim.

10

Research Graduation gate — Only when Research Route is used. See references/research_route_policy.md and templates/research_route; preserve failed evidence before git reset --hard on isolated research branches only, then route through review and cleanup.

Hard rules: Do not execute the supplied task here. Reconcile existing harness before adding/replacing. Audit AGENTS.md every run; patch only stable facts and remove stale task-specific pointers. Dynamic state → .harness/ only: active_slice in .harness/state.m...
