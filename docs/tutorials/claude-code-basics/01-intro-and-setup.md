# 01 — 认识 Claude Code + 上手

## 它不是"更聪明的 ChatGPT"

你可能已经在用 ChatGPT 或 Claude.ai 帮忙——问概念、改语法、解释论文。这种用法本质是**问答**：你问一句，它答一句，答完就结束了。

Claude Code（以下简称 CC）是不一样的。它是一个**在终端里运行的项目搭档**，能做的事包括：

| 你能做的 | CC 能做的 |
|---------|----------|
| `cd ~/research/image-classification` | 进入你的项目目录 |
| `ls`、`cat`、`grep` | 读你的文件、搜索代码 |
| `python train.py`、观察输出 | 运行命令、读输出、根据结果决定下一步 |
| `git diff`、`git log` | 读 git 历史、理解代码是怎么演化的 |
| 改代码、跑测试、看报错、再改 | 改代码、跑测试、看报错、再改——**闭环** |

关键区别在于**闭环**。你用 ChatGPT 问"这段代码为什么报错"，它给你一个分析。你用 CC 处理同样的问题，它会读代码→改代码→运行→看到新报错→再改→跑到通过为止。你只需要在旁边看，按 `Esc` 就能随时打断纠正方向。

**一句话理解 CC 的能力模型**：它不是一个更聪明的问答机器，它是一个能读取你的项目、在项目里执行操作、并根据结果调整行为的终端 agent。

## 科研场景全景

在你开始之前，先看一下 CC 能在科研中覆盖哪些事。不要求你现在就理解每一步怎么做——后续模块会逐一展开。

```
你的科研日常                        CC 的参与方式
─────────────────────────────────────────────────────
读一篇新论文的开源代码            →  让 CC 解释仓库结构、核心逻辑
在自己的数据上复现 baseline       →  CC 写数据加载、配置参数、运行
实验结果不符合预期，想排查         →  CC 读日志、加调试输出、定位问题
改了模型结构，想对比消融实验       →  CC 批量改参数、跑实验、收集结果
数据预处理总是出 bug               →  CC 排查数据 pipeline、写测试
画出来的图不好看                   →  CC 调 matplotlib 参数、对比原论文图
和同门共享实验配置                →  共用 CLAUDE.md，git 协作
一个实验断断续续跑了一周           →  会话管理，恢复之前的上下文
```

**本教程不要求你学任何配置**——不写 hooks、不创建 skills、不连 MCP 服务器。我们只用 CC 装好就能用的功能，覆盖上面这些场景。

## 3 分钟上手

### 1. 确认安装

```bash
claude --version
```

如果没有，参考[官方安装指南](https://docs.claude.codes/install)。

### 2. 进入项目目录

CC 的一切工作都基于**当前目录**。它在哪个目录启动，就把哪个目录当成"项目根目录"。

```bash
cd ~/research/image-classification   # 你的科研项目
```

**这一条非常重要**：CC 需要看到你的项目文件才能理解项目。不要在家目录或桌面启动 CC——它看到的文件决定了它能做什么。

### 3. 启动，说第一句话

```bash
claude
```

你会进入交互式界面。试试说：

```
看看这个项目的结构，告诉我它是做什么的
```

CC 会用 `ls`、`cat`、`grep` 等命令探索你的项目，然后给你一个结构化总结。这不是魔法——它真的在运行命令，读你的文件。

### 4. 试一个具体任务

如果你项目里有 Python 代码：

```
这个项目里有没有训练脚本？它接受什么参数？帮我看看
```

CC 会找到脚本，读它的 argparse 或配置，然后告诉你。

**到这里，你已经完成了第一次交互。** 但要让 CC 真正好用，你还差关键一步——下一节讲。

## 本节要点

- CC 不是在聊天框里问答——它是在你的项目里执行操作、读结果、调整行为的终端 agent。
- **在项目目录里启动 CC**，让它看到你的文件。
- 试着让它探索一下你的项目结构，感受一下它能"看到"什么。
