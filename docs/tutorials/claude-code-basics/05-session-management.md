# 05 — 会话管理

前面四节都是在"一次对话内"工作。但科研的现实是——一个实验跑三天，中间要开会、改方向、同时推进多个任务。CC 的会话管理决定了"用起来顺手"还是"每次都要从头解释"。

Claude Code 最佳实践中，"管理你的会话"是篇幅最长、最实操的章节。这一节是基础版最核心的一章。

## 先看清一个问题：上下文是什么

每次你用 CC，它能看到的内容包括：

```
┌─ 系统提示（固定，CC 的角色和规则）
├─ 工具定义（CC 能用的工具列表）
├─ CLAUDE.md（你的项目说明）
├─ 对话历史（你和 CC 说过的所有话 + CC 做过的所有操作）
├─ 你 @ 引用的文件内容
└─ 命令输出（CC 运行的命令结果）
```

这些加起来，就是当前会话的**上下文**。上下文有上限，满了之后 CC 会变慢、记不住早期对话、或被迫压缩。

**上下文不是越多越好**——这是 Claude Code 团队反复强调的。[1] 垃圾上下文会稀释关键信息，让 CC 在无关细节里迷失。

[1]: 见 Anthropic 工程博客 [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)。

## 工具一：`/clear` — 重置对话

**什么时候用**：话题完全变了，前面的对话没有保留价值。

```
# 你刚才让 CC 帮你修了一个数据加载的 bug，修完了。
# 现在你想做一件完全无关的事——比如写论文里的 related work 讨论。

/clear
```

`/clear` 会清空对话历史。CC 仍然会读 CLAUDE.md（项目说明书还在），但不会再"记得"刚才修 bug 的细节。

**科研场景**：

- 修完一个 bug，开始新任务 → `/clear`
- 分析了实验 A，转而分析实验 B → `/clear`
- CC 的行为开始"不对劲"（受早期无关对话影响）→ `/clear`

**不要频繁 `/clear`**：如果你刚让 CC 深入理解了一个代码库，马上 `/clear` 等于让它重新来过。只有话题彻底切换时才清。

## 工具二：`/compact` — 压缩而不丢失

**什么时候用**：上下文快满了，但当前任务还没做完，需要保留关键信息继续。

`/clear` 是"全忘"，`/compact` 是"做笔记"——CC 会把对话历史总结成一段简短摘要，保留做了什么、改了哪些文件、当前状态，然后释放出空间继续工作。

```
/compact
```

不加参数的 `/compact` 会让 CC 自动判断保留什么。

### 指定保留内容

科研场景中，你通常希望保留比默认更多的技术细节：

```
/compact 保留以下内容：所有修改过的文件列表、实验配置参数、
当前运行的命令和输出、未解决的 bug 描述。
```

你甚至可以在 CLAUDE.md 里写一条约定，让每次压缩都按你的标准来：

```markdown
# CLAUDE.md 中加上
## 压缩策略
压缩时始终保留：所有修改文件的完整路径、当前激活的 conda 环境、
正在运行的实验配置、最近的报错信息和修复尝试。
```

### `/clear` vs `/compact` 决策表

| 场景 | 用哪个 | 原因 |
|------|--------|------|
| 修完 bug，开始看论文 | `/clear` | 话题完全切换，旧对话没用 |
| 实验分析到一半，上下文太长 | `/compact` | 任务继续，但需要释放空间 |
| CC 行为异常（幻觉增多、忘记说了什么） | `/clear` | 上下文已污染，压缩也救不回来 |
| 刚做完复杂重构，准备继续优化 | `/compact` 后继续 | 保留重构结果，清出空间做下一步 |

## 工具三：`Esc` + `/rewind` — 打断和回退

### 用 `Esc` 打断

CC 正在做的事你不满意——方向偏了、理解错了、或者你发现自己没说清楚——按 `Esc`。

按一次 `Esc`：CC 停下来，等你给新指令。
按两次 `Esc`：强制中断，CC 完全停下。

你不需要等 CC 做完才能纠偏。这也是 Claude Code 最佳实践中"尽早且经常改正方向"的含义——**发现不对立刻打断，不要让它跑完再后悔。**

### 用 `/rewind` 回退

`/rewind` 让你回到会话的某个之前的状态。CC 会在运行关键操作（修改文件、执行命令）前自动创建检查点。

```
/rewind
```

CC 会列出最近的检查点，你选一个回退。回退之后，检查点之后的所有改动都会被撤销。

**科研场景**：你让 CC 重构数据加载代码，改到一半发现方向不对。`Esc` 打断 → `/rewind` 回到重构前 → 重新描述需求。

### "说人话"也能回退

你不用非得记命令：

```
撤销刚才那个改动
回到你改 transforms.py 之前
```

CC 能理解自然语言的撤销意图。

## 工具四：`--continue` 和 `--resume` — 跨会话继续

这是科研场景中最被低估的功能。实验跑了好几天，你要中断 CC 会话去开会、睡觉、做别的事——回来后怎么继续？

### 给会话命名

在会话中：

```
/rename mixcut-experiment
```

给会话一个有意义的名字，方便之后找到。

### 继续最近的会话

```bash
claude --continue
```

CC 会加载你最近一次会话，从上次停下的地方继续。**对话历史、执行过的命令、改过的文件——CC 都知道。**

### 恢复指定的会话

```bash
claude --resume
```

CC 会列出你最近的所有命名会话，选一个恢复。或者直接：

```bash
claude --resume mixcut-experiment
```

**科研场景**：小李的 MixCut 实验需要跑 50 个 epoch（约 3 小时），他启动训练后就退出了。第二天回来：

```bash
cd ~/research/image-classification
claude --resume mixcut-experiment
```

CC 恢复上下文，小李说：

```
训练已经跑完了，日志在 experiments/mixcut/logs/train.log。
帮我分析结果，和 baseline 对比。
```

CC 知道项目结构（CLAUDE.md 还在）、记得之前的实验配置（压缩摘要保留了下来），直接开始分析。

## 工具五：用 Subagents 隔离调研

这是"使用"而非"配置"——你不需要创建 subagent 定义文件，直接说就行。

```
用 subagents 调查一下我们的数据增强 pipeline 是怎么处理
不同尺寸输入图片的，有没有现成的 resize 逻辑我可以复用。
```

CC 会启动独立的 subagent 去调研，完成后再回到主会话汇报。**subagent 的中间过程不会污染你的主对话上下文**——你只看到结论。

科研中适合用 subagents 的场景：

| 场景 | 怎么说 |
|------|--------|
| 调研代码库中某个模式 | "用 subagents 调查 X 在项目里是怎么实现的" |
| 并行读多篇论文 | "用 subagents 分别读这三篇论文的 PDF，各自总结方法论" |
| 代码审查 | "用 subagents 审查我刚改的 X，找出边界情况和潜在 bug" |
| 探索不熟悉的代码 | "用 subagents 搞清楚 Y 模块的调用链和依赖关系" |

**什么时候不用 subagents**：简单问题（一个 grep 就能回答的）、强依赖顺序的任务（必须先 A 再 B 再 C）。

## 会话管理全景决策图

```
启动 CC
  │
  ├── 新任务（和之前完全无关）
  │     └── /clear 后开始
  │
  ├── 继续之前的任务
  │     ├── 刚退出，马上回来 → claude --continue
  │     └── 隔了一天，指定会话 → claude --resume <名字>
  │
  ├── 任务进行中，上下文太长了
  │     └── /compact [保留关键信息]
  │
  ├── CC 做偏了
  │     ├── 还能救 → Esc 打断，纠正方向
  │     └── 救不回来 → /rewind 回退到检查点
  │
  ├── 需要调研某个子问题
  │     └── "用 subagents 调查 X"
  │
  └── CC 行为异常（幻觉、健忘）
        └── /clear 重置
```

## 本节要点

- 上下文是有限资源，需要主动管理。不是越多越好。
- `/clear` 用于话题切换，`/compact` 用于压缩继续。
- `Esc` 打断是日常操作——发现偏了就停，不要让它跑完。
- `--continue` / `--resume` 让长周期实验不丢上下文。
- Subagents 是"使用"功能——说"用 subagents 调查 X"就行，不用配置。
- **关键习惯**：给会话命名（`/rename`），方便跨天恢复。
